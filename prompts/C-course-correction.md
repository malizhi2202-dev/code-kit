# C-course-correction — 重大变更影响评估

> 仅在 sprint/change 执行中出现会改变范围、目标、架构、UX、公共契约或交付时间的变更时使用。小修复回原 task，不启动本流程。

## 流程

1. 读取 `STATE.md` 和当前 change 的全部已有工件；只读检查当前 diff。
2. 记录触发问题、证据、影响范围和缺失材料；缺少 REQUIREMENT 或 TASK 时先回对应阶段。
3. 逐项评估 REQUIREMENT/AC、DESIGN/ADR、UI-DESIGN、TASK 依赖、TEST/REVIEW、代码与交付风险。
4. 给出候选：直接调整、缩减 MVP、重排任务、回退；每项写代价、风险、时间影响和未决点。
5. 生成 `.specs/<id>/COURSE-CORRECTION.md` 草案，逐项向用户展示“保留/编辑/跳过”。未经批准不得更新任何原工件。
6. 批准后更新受影响工件，标注变更来源，并回到最早受影响阶段；下游产物失效时显式标记，不能继续使用旧结论。

## 最终结构

- 触发问题与证据
- 影响矩阵（工件 / 代码 / 风险）
- 候选方案与推荐
- 已批准的逐项变更
- 重新执行的阶段与验收条件
- 延后项、负责人和复查触发条件
