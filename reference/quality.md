## 1. 安全

安全不是阶段，是每一行碰用户数据、鉴权、外部系统代码的约束。外部输入一律敌意，密钥神圣，鉴权检查强制。

### 1.1 先威胁建模（5 分钟）

1. **画信任边界**：HTTP 请求、表单、上传、webhook、第三方 API、消息队列、**LLM 输出**，以及"看起来内部"的值（别的进程的命令行/环境变量、共享卷文件名、job payload 里的路径）。**信任看谁写的，不看哪个通道送来的。**
2. **点名资产**：凭证、PII、支付数据、管理操作、资金流。
3. **对每个边界跑 STRIDE**：Spoofing（认证/签名）、Tampering（完整性/参数化/HTTPS）、Repudiation（审计日志）、Information disclosure（加密/字段白名单/通用错误）、DoS（限流/大小上限/超时）、Elevation（鉴权/最小权限）。
4. **用例旁写滥用用例**："我会怎么滥用它？"——那就是第一条测试。

说不清一个功能的信任边界 = 还没准备好保护它。

### 1.2 三档边界纪律

**总是做**：边界校验所有外部输入；参数化所有 DB 查询；输出编码防 XSS；外部通信 HTTPS；密码用 bcrypt/scrypt/argon2；安全头（CSP/HSTS/X-Frame-Options/X-Content-Type-Options）；会话 cookie `httpOnly+secure+sameSite`；发布前跑包管理器原生审计（针对提交的 lockfile）。

**先问人**：新增认证流/改鉴权逻辑；存新类别敏感数据；新外部服务集成；改 CORS；加文件上传；改限流；提权/加角色。

**绝不做**：提交密钥；日志打印敏感数据；信任客户端校验；为方便关安全头；对用户数据用 `eval` / `innerHTML`；把会话 token 放 localStorage；把栈/内部错误暴露给用户。

### 1.3 常见漏洞的正确姿势

- **注入**：`db.query('... WHERE id=$1',[id])` / ORM 参数化；不拼字符串。
- **认证**：密码哈希（salt rounds ≥ 12）；会话密钥从 env；cookie 四件套；登录限流；重置 token 过期。
- **XSS**：框架自动转义；必须渲染 HTML 先 sanitize（DOMPurify）；不 `innerHTML = userInput`。
- **越权**：认证之后还要**授权**——每个资源查 owner/tenant/role；越权与不存在统一 404，避免探测。
- **配置**：helmet/CSP/CORS 白名单，不用 `*`。
- **敏感数据**：响应前剔除 `passwordHash/resetToken` 等；密钥从 env 读，缺失就抛错。
- **SSRF**：用户影响的服务端 URL（webhook/导入/图片代理/链接预览）→ 协议+host 白名单，解析所有 IP 且任一非 unicast 即拒，`redirect:'error'`；高危面用固定 IP 连接或过滤 agent（注意 DNS rebinding TOCTOU）。
- **文件上传**：类型白名单 + 大小上限 + 必要时查 magic bytes，不信扩展名。
- **破坏性路径操作**：删除/移动/覆盖的目标必须①解析符号链接后位于白名单根下②至少比根深一层③带"属于我"的证据（且在操作前读取）；拒绝时记录并停止，**不许回退到更宽泛的默认路径**。
- **限流**：认证端点单独更严；多进程/多实例必须用共享 store（Redis/Upstash），进程内计数实际上限 = max × 实例数。

### 1.4 依赖与供应链

- 审计只报已知公告，不证明包可信、不证明漏洞代码可达。
- 分级：critical/high 且可达 → 立即修；不可达 → 尽快；moderate 生产可达 → 下个发布；dev-only → 排期；low → 常规升级。延期必须写理由 + 复查日期。
- 找到安装边界（workspace 根 / lockfile）与唯一包管理器；`packageManager`、lockfile、CI 不一致就停；钉版本；首次执行前禁止依赖脚本，逐包审批；禁止 `audit fix --force` 自动改；验证 registry 签名/provenance；新依赖审查 owner、维护度、发布年龄、传递依赖、typosquat（`cross-env` vs `crossenv`）。

### 1.5 密钥

`.env.example` 提交占位；`.env` / `.env.local` / `*.pem` / `*.key` 不提交；提交前 `git diff --cached | grep -i "password\|secret\|api_key\|token"`。
**一旦密钥进过远端 → 视为已泄露：先吊销/轮换，再清历史**；只删行或改历史不够。

### 1.6 隐私

"能不能被读"是安全；"该不该持有、持多久"是隐私。
- 分类：非个人 / 个人（PII：姓名、邮箱、IP、设备/用户 ID）/ 敏感（健康、财务、位置、生物、证件、未成年人）。
- 最小化 + 声明用途；"以后可能有用"不是用途，是泄露面。
- 每个个人数据存储有 TTL 和可用的删除路径（含备份、缓存、搜索索引、分析副本）。
- 支持导出/更正/删除（按辖区）；第三方共享（含分析/广告/LLM 厂商）要同意 + 数据处理协议。
- 不要把 PII 写进遥测日志。

### 1.7 AI / LLM 功能

- **模型输出 = 不可信输入**：绝不直接进 `eval` / SQL / shell / `innerHTML` / 文件路径；解析→校验→编码。
- **提示注入**：系统提示不是安全边界；权限在代码里，不在提示词里。
- **别把密钥/他人数据/完整系统提示放进上下文**（会被回显）。
- **限制工具权限**：最小作用域，破坏/不可逆操作要确认，校验每个工具参数。
- **限制消耗**：token、速率、循环/递归深度。
- **RAG 隔离**：向量库是信任边界；按租户分区；索引前验证文档。

### 1.8 安全审查清单

- [ ] 密码哈希、会话四件套、登录限流、重置过期
- [ ] 每个端点有鉴权 + 授权；用户只能访问自己的资源；管理操作验角色
- [ ] 边界校验；参数化查询；输出编码；服务端 URL 白名单；破坏性路径三项检查
- [ ] 无密钥入库；敏感字段不出现在响应；PII 已分类/最小化/有保留期/删除路径可用
- [ ] 安全头、CORS 白名单、依赖审计、错误不暴露内部
- [ ] 单一权威 lockfile + frozen install；脚本默认禁；新依赖已审查
- [ ] LLM 输出未直接执行；工具权限受限；提示里无密钥/他人数据

## 2. 性能

**先测量再优化。** 没有测量的优化是猜；猜会带来不解决问题的复杂度。

### 2.1 工作流

```
MEASURE（真实基线）→ IDENTIFY（真实瓶颈）→ FIX（只修那个）→ VERIFY（同法复测，保留或回滚）→ GUARD（监控/预算防回归）
```

**测量两条腿**：合成（Lighthouse/DevTools，可控可复现，适合 CI 与定位）+ RUM（web-vitals/CrUX，真实用户，验证修复有效）。
**按症状选起点**：
- 首屏慢 → bundle？TTFB（DNS/TCP/TLS/服务端等待）？渲染阻塞资源？
- 交互卡 → 主线程长任务（>50ms）、重渲染、布局抖动。
- 导航后慢 → API 瀑布、N+1 请求、客户端渲染。
- 后端 → 单端点慢（查 SQL/索引）/ 全端点慢（连接池、内存、CPU）/ 间歇慢（锁、GC、外部依赖）。

### 2.2 常见瓶颈与修法

- **N+1**：`include`/`join` 一次查；循环里查是信号。
- **无分页**：列表从第一天分页。
- **索引**："加索引"是猜，query plan 是测量：`EXPLAIN ANALYZE`。看到 `Seq Scan` 大表 = 没有可用索引；估算行数与实际差一个量级 = 统计过期；scan 上有 `Sort` = 索引覆盖过滤但不覆盖排序。按**查询形状**建复合索引（等值列在前，范围/排序列在后）。不适用：低选择性、前导通配符、列上有函数、写多表（每个索引都收写税）。加完重跑 plan，没改变计划就回滚。
- **连接池**：每进程一个池，`max × 实例数 < DB max_connections`；池大于 DB 并发能力只是把队列挪进 DB。无界实例用 pgbouncer/RDS Proxy。
- **图片**：宽高必填防 CLS；LCP 图 `fetchpriority="high"` + `srcset/sizes` + AVIF/WebP；首屏外 `loading="lazy" decoding="async"`。
- **React 重渲染**：稳定引用、`React.memo`（贵组件）、`useMemo`（贵计算）——不要到处用。
- **Bundle**：懒加载重功能、路由级拆分；先 profile，别迷信改 import 风格。
- **缓存**：只缓存"贵且读远多于写"的。层选择：进程内（单实例、允许各实例漂移）/ 共享 Redis（实例必须一致）/ CDN（公开且按 URL 相同，失效难撤回）。**key 必须包含所有改变响应的输入**（租户、locale、权限、flag），漏 viewer 就是把 A 的数据给 B。选一种失效策略（TTL / 事件 / 版本化 key）。防击穿：`stale-while-revalidate` 或把并发 miss 合并成一个 in-flight 重算。**不要缓存**：余额、权限、结账库存等"过期即正确性 bug"的数据。

### 2.3 验证与回滚

- 同命令、同条件、同预算复测；一次只改一个；先超过运行间噪声再谈提升。
- 超过阈值且测试绿 → 保留（commit 里写前后数字）；在噪声内 → 回滚；变差 → 回滚；提升但测试红 → 回滚。
- **"中性"是回滚，不是保留。** 保留的代码要维护一辈子。
- 正确答案被指标绑架也算回归：跳校验、缓存必须新鲜的东西、删掉承重的 `await` = 回归。
- **记录每次尝试（含回滚）**：`| 想法 | 基线→结果 | 结论 | 原因 |`，否则下季度再试一遍。
- **防回归**：合成 CI 预算（bundle < 200KB gzip 初始、CSS < 50KB、首屏图 < 200KB、字体 < 100KB、API p95 < 200ms、Lighthouse ≥ 90）+ 字段监控（p75 显著移动才告警）。

## 3. 可观测性

上线后看不到 = 故障无法定位。

- **日志**：关键路径入口/出口/异常都有；结构化（JSON）；含 trace-id；**不含 PII/密钥/token**（grep 验证）；错误日志有足够上下文。
- **指标**：业务关键 metric（转化、错误率、关键时长）；关键 endpoint 的 RED（Rate/Errors/Duration）。
- **追踪**：跨服务调用串通；慢 span 可定位。
- **告警**：关键失败有告警 + runbook 链接；无噪音；`/health` 区分 liveness / readiness。
- **埋点纪律**：事件名稳定、属性有界、不上报敏感数据；埋点与功能同批提交。

## 4. 五轮测试矩阵

> 阶段 5 的展开。每轮 ✅必跑 / ⚠️部分 / ❌跳过 + 理由；禁止"暂时跳过"。

### 第 1 轮 · 功能
- AC → 用例矩阵（unit/integration/e2e/manual），每条 AC ≥ 1 覆盖。
- 覆盖率：默认 80%，core ≥ 90%；报命令与输出。
- 边界 ≥ 3：空、极大、极小、Unicode、null；错误路径必须有测试。
- UAT 脚本：前置 / 步骤 / 期望 / 通过失败。
- **T1–T6**：晦涩、脆弱、重复、mock 滥用、覆盖率幻觉、架构错配。

### 第 2 轮 · 性能
- 预算来自非功能性需求（没有就停）。
- 前端：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1；bundle 与上版对比。
- 后端：N 倍 QPS 下 p95/p99/错误率；慢查询 `EXPLAIN ANALYZE`；N+1 必查。
- 结论只写"达标 / 退步 X% / 接近阈值"。

### 第 3 轮 · 安全
- 依赖：`npm audit --production` / `pip-audit` / `govulncheck` / `cargo audit` + 镜像 `trivy`；无 high/critical 或显式接受。
- 密钥：`trufflehog` / `gitleaks`；0 命中，命中立即轮换。
- SAST：Semgrep / CodeQL / Bandit；无 high，medium 有处理记录。
- OWASP Top 10 逐项标 ✅/❌不适用/🟡待补。

### 第 4 轮 · 兼容
- 前端：Chrome/Firefox/Safari/Edge 最新两版；iOS Safari / Android Chrome；视口 360/768/1024/1440。
- 数据迁移：生产快照预演；耗时 → 维护窗口（>30s 的 ALTER 必走）；down 测过；backfill 验证；NOT NULL 旧行处理；改类型不丢/不截断/不溢出。
- 跨版本：旧 schema 数据新代码可读写；API 版本兼容；UTF-8/16/locale。

### 第 5 轮 · 可观测
- 日志 / 指标 / 追踪 / 告警 / 健康检查逐项验证（见 §3）。

## 5. UI 基线（仅 greenfield / 明确换皮时强制）

Brownfield 默认**沿用观察到的视觉语汇**（见 `prompts/2a-ui-design.md` 的 brownfield 视觉语汇对齐），不套本节；用户明确要求换调性（L-restyle）或新建项目时才强制。

- **颜色**：用 OKLCH 设计主色 + 中性梯度；有遗留约束（品牌色/旧浏览器）必须显式声明例外。
- **字体**：避开 Inter / Roboto / Arial / Helvetica / system-ui 默认（它们是 AI-slop 信号）；必须用时说明为什么不能换。
- **间距/圆角**：非线性 scale（6–8 档），圆角词汇 ≤ 5 个值。
- **动效**：统一缓动曲线 + 2–3 档时长；不弹跳、不动 layout 属性；响应 `prefers-reduced-motion`。
- **阴影**：at rest 平面；alpha ≤ 0.15；不叠多层纵深。
- **反 AI-slop**：无紫蓝渐变、无三卡并排 hero-metric、无玻璃拟态、无 emoji 充图标、无编造数据/好评/logo 墙。
- **占位符诚实**：图标 `[icon]`、头像首字母、图片 aspect-ratio 占位、缺数据反问（禁止编造）。
- **可访问性底线**：对比度 ≥ WCAG 2.1 AA、键盘可达、焦点环可见、label 显式关联、图片 alt。
