1 · 产品全景

logsearch 是一套轻量级分布式日志搜索平台：中心侧集中管理“去哪儿搜、搜什么、结果怎么解析”，边缘侧用 Agent 在业务机器上受限执行，日志不出机器；再加一层 LLM 能力，把日志目录发现、字段解析、结果分析、日常操作变成“可确认的智能动作”。

1.1 一句话定位

中心
控制中心 control-center

HTTP 管理 API + RBAC + 配置版本化 + 任务调度 + gRPC Agent 服务 + 审计。唯一的状态与规则来源。

边缘
日志 Agent

主动外连、HMAC 双向流、领取任务租约、在本机受限执行、截断/脱敏/解析后分批上报。

智能
LLM 与记忆

公共模型与私有模型、分析技能、解析 Agent、剧本、场景模板、对话记忆——把“怎么做”沉淀成资产。

1.4 这个产品不做什么（边界）

明确不做

  • 不做日志采集搬运：只在目标机器上就地搜索，命中行才回传（且完整结果落临时文件、DB 只存摘要）。
  • 不做通用任务编排：执行边界固定在“日志目录 + 声明式命令模板”，不允许任意 shell。
  • 不做日志存储/检索引擎：不是 ES 替代品，不建全量索引。
  • 不做 LLM 的自动落库：模型产出必须经人确认才会变成配置或动作。

安全底线（贯穿全篇）

  • 命令模板必须含 {files}；参数只进声明过的槽位，shell:true 一律拒绝。
  • gRPC 逐消息 HMAC-SHA256 签名 + ±5min 时间窗；agent_secret AES-GCM 落库、Agent 侧 0600 落盘。
  • 输出默认脱敏 authorization / token / password / cookie / secret。
  • Agent 不信任控制中心：租约解析时二次校验 shell、占位符与限制默认值。

2.2 执行模型（任务 / 租约）

一句话：一次搜索 = 一个 Job（中心侧的状态机）+ 每个 Agent 一份 Lease（带时限的执行许可）。

Job 状态机

created→ dispatching→ running→ completed

分支终态：partial_success（部分 Agent 成功）、failed、canceled、timed_out。

单 Agent 结果语义

  • success：有命中行
  • no_match：搜到了但没命中
  • no_files / no_source_matched：按成功统计（空文件集合 ≠ 失败）
  • source_missing：日志源路径已不存在 → 提示回滚或改配置
  • partial_success：输出被截断（10MB / 10 万行上限）
  • timed_out / canceled / failed

租约里有什么

job_id / lease_id幂等与去重键
deadline过期即作废，Agent 自行放弃
files / source已解析的日志源与文件集合
argv渲染后的参数数组（占位符已注入）
limits截断行数/字节、超时、脱敏开关
parse提取规则（正则 / JSON / 分隔符）

回传：JobResultBatch（命中行分批）→ JobFinished（终态 + 元信息）。

断线补偿：Agent 重连后上报 running_jobs，中心对未过期任务补发租约、对已取消/超时任务补发取消；Agent 按 job_id 去重，保证“最多执行一次上报、绝不重复计费式重跑”。

2.4 记忆与知识

一句话：把“一个人的经验”变成“项目的资产”——对话有记忆、解析有技能、流程有剧本、整套配置可以打包成场景。

对话记忆

会话 ChatSession + 消息 ChatMessage 服务端落库；可在项目内或平台级（跨项目）查看历史，回放当时的建议与结论。

分析技能 / 解析 Agent

技能=分析提示词资产；解析 Agent=针对某类日志格式的解析器资产。均可在项目内建私有、由平台下发公共。

剧本 Playbook

把多步操作固化成可执行流程，可分配给指定项目；对话里可直接“跑剧本”。

两种分发模型不一样，这是设计选择不是缺陷：
① 公共技能 / 公共解析 Agent（project_id = 0）：全局可见——所有项目都能直接引用，没有“逐个分配”这一步（项目侧查询是 本项目 ∪ 公共）。
② 剧本：分配制——可见范围 = enabled_for_all（对所有项目开放）∪ 被显式分配到的项目；未开放也未分配的剧本，项目里看不到。
③ 模型配置：平台默认（project_id = 0）+ 项目私有可覆盖。
需要“只给某些项目用”时用剧本；需要“人人都能用”时用公共技能。

场景 Scene

可复用工作模板：技能 + Agent + 日志源 + 命令 + 剧本打包，一键事务式实例化为一个新项目（技能名→ID 自动重映射）。

两处“记忆”别混淆：① 会话记忆（人机对话历史，回答“我们上次聊到哪”）；② 配置资产（技能/解析器/剧本/场景，回答“这类日志我们怎么处理”）。前者是记录，后者是可执行资产。

2.5 审批与人工闸门

一句话：所有会让模型“改系统”的路径都设了人确认——模型可以建议，只有人能生效。

闸门模型可以做的必须人确认的机制
提取规则 · 按样本生成草稿按样本行做确定性启发式推断，生成正则/JSON 规则与字段映射草稿（不调用大模型）点「校验预览」看解析结果，再「提交生效」（生成新版本，可回滚）规则版本化，可回滚
日志目录发现给出目录是否符合标准、日志格式识别结论批准 / 拒绝（有效性确认标记）；建为日志源是独立动作，不要求先批准发现记录状态机
日志分析对命中日志给出结论、可疑项、建议结论只进分析记录，不自动改配置分析记录 + 人工采用
对话中的动作生成“建议动作卡”（如添加日志源、跑剧本）点「确认执行」才真正调用写接口/chat/execute + CSRF
场景实例化—人点「从场景创建项目」，事务式落地审计 scene.instantiate

实现边界：模型不可用时（未配 LLM / 调用失败），页面必须给出明确引导而不是空白——自然语言搜索走本地规则解析，不依赖大模型即可用。

5.1 登录与全局导航

它是什么：唯一的进入口。平台没有自助注册，账号由平台管理员创建；登录后按角色渲染左导航。

数据概念

用户
用户名 + 口令（bcrypt）+ 角色 + 状态（active / disabled）
会话
服务端 Session；写操作额外要求 X-CSRF-Token
审计
登录成功/失败都留痕

界面与操作

  1. 打开 /loggen/ → 未登录自动跳登录页。
  2. 输入用户名 / 密码 → 点「登录」。
  3. 成功后进入对话助手（/chat，默认首页）；需要项目总览走侧栏「工作台」。顶栏右侧「文档资料」可页内打开本产品设计文档与界面原型（弹窗右上角另有「在新标签打开」）。未登录也能看：登录页卡片下方即有此入口，或直接访问 /loggen/docs/product-design.html。

注意：被禁用（disabled）的账号即使口令正确也会被拒；连续失败不锁定账号，但会持续写审计，排查时按“操作者 + 动作”筛审计日志。

5.3 对话（平台级 /chat）

它是什么：把“搜日志、看配置、动配置”用自然语言串起来的入口。既能问（只读分析），也能改（生成动作卡，人确认后执行）。

数据概念

会话
chat_sessions：属于某个项目，或平台级（project_id = 0）
消息
chat_messages：角色（user/assistant）、内容、附带的动作卡与执行结果
范围
顶栏右侧「范围」选择器 + 输入卡左侧 ✦ 快捷切换：平台=跨项目总览；具体项目=直接调用项目功能

界面与操作

  1. 左栏顶部范围条显示当前范围（平台 · 全部项目 / 项目 · X（仅本项目））。
  2. 「＋ 新建对话」开新会话；历史会话按项目分组、可折叠，搜索会穿透折叠直达命中会话。
  3. 平台模式下：左栏按项目分组，平台组置顶；切到具体项目后，左栏只列本项目，项目层级消失。
  4. 底部悬浮输入卡输入问题，回车发送；回答里出现「建议动作卡」时，点「确认执行」才真正落库。
  5. 确认执行的回执（含任务号 / 批次号 / 项目号）会留在对话流里：接着说「取消刚才那个任务」这类多轮指代可直接解析执行。
  6. 回执卡带深链：搜索作业 →「在单次搜索中查看」直达结果区；压测批次 →「查看批次结果」直达批次详情（命中汇总 + 下载）。
  7. 复合需求出「一次完成多步」计划卡（如一句话新建项目 + 连建日志路径 / 命令 / 规则，确认一次全部落位）。
  8. 「📖 示例」面板：八轮完整演示话术，一键填入。
  9. 长回复折叠为 8 行，可「展开全文」；超过 60 条的历史按窗口回放，向上滚动「载入更早」。

实现边界：平台级对话在没有项目上下文时，涉及改配置的动作会降级为“引导式回答”，不会猜一个项目去改。未配置 LLM 时页面给出配置引导（前往平台设置 · 公共模型配置）。

5.4 项目与项目导航

它是什么：项目是所有配置的隔离边界——日志源、命令、规则、样本、Agent 绑定、成员、LLM 资产全部挂在项目下。

  1. 「创建新项目」：填项目名与描述 → 创建。
  2. 创建成功后一次性显示 appid / secret：立刻保存，页面刷新后不再展示。
  3. 列表显示项目、描述、appid、状态、创建时间；点击进入项目详情。

项目页顶部标签条（二级导航）

  • 搜日志（单次 / 批量 / 历史三个页签）

  • 成员管理（仅 PA 可见）

5.5 日志搜索

它是什么：产品的心脏。四种用法覆盖从“我大概知道要搜什么”到“我只想描述现象”。

单次搜索

选命令 + 关键词 + 时间范围，立刻拿到结果。最常用。

自然语言搜索

如“过去 7 天 heimdallr 的 ERROR 日志”，本地规则解析成命令参数后执行，无需大模型。

语义搜索

一句话描述现象，由 LLM 规划检索（需先配置模型）。

批量搜索

指定命令、并发、每 Worker 请求数与执行机器（默认全部在线、可勾子集），创建批次做扫描或压测。

控件作用说明
页签：单次 / 批量 / 历史切换搜索模式 / 回看历史对话搜索在全局对话工作台（/chat），不在本页
命令选择选择搜索命令模板模板内 {files} 由 Agent 注入文件集合
关键词作为参数进入命令槽位只进 argv，不做 shell 拼接
时间范围限定日志时间窗影响 Agent 侧文件与行筛选

5.6 日志文件路径（搜索配置 · 子页签）

它是什么：告诉 Agent“去哪找日志”。它是路径与匹配模式，不是日志内容。入口：项目页「搜索配置」页签 → 子页签「日志文件路径」（?sub=sources，可深链）。

字段含义示例
路径目录或文件绝对路径/var/log/nginx
模式文件名匹配（glob）*.log · access.log*
描述给人看的用途说明网关访问日志（含 trace）
状态启用 / 禁用禁用后不参与搜索，配置保留
版本每次修改 +1可「回滚」到上一版本

操作：添加（路径 + 模式 + 描述）→ 提交生效（= 生成新版本，可回滚）→ 需要时禁用/删除/回滚。权限：查看为项目成员，写操作需项目管理员。注意：路径不存在时结果会出现 source_missing，应改配置或回滚，而不是反复重试。

5.7 搜索语句模板（搜索配置 · 子页签）

它是什么：把“怎么搜”固化成模板，避免每个人写不一样的命令。

关键规则

  • 命令模板必须包含 {files} 占位符，由 Agent 注入解析出的文件集合。
  • 参数只进声明过的槽位（如 {keyword}、{since}），不做字符串拼接。
  • shell:true 一律被拒绝——这是平台的硬约束。
  • 同样版本化，可回滚。

操作步骤

  1. 「添加命令」：填名称、命令模板、参数列表（参数名 / 类型 / 是否必填 / 白名单 / 长度上限）。
  2. 「＋ 添加参数」按需增加槽位。
  3. 「提交生效」= 生成一个新版本（可回滚），之后即可在日志搜索里被选中；不是"直接覆盖当前配置"。
  4. 命令列表显示名称、命令、参数、版本；可删除或回滚。

5.8 字段解析配置（搜索配置 · 子页签）

它是什么：把非结构化日志行变成结构化字段（TraceID、状态码、耗时、上游地址…），搜索结果的“解析字段”就来自这里。

字段含义取值
名称规则用途nginx access 标准解析
类型解析方式正则 / JSON / 分隔符
模式正则表达式或分隔符定义^(?<ip>\S+) - - \[(?<time>[^\]]+)\]
字段从捕获组映射出的字段名ip, time, method, status, rt
时间字段用于时间筛选的字段time

5.14 日志分析

它是什么：项目级智能分析台。让模型读一段真实日志，给出结论、可疑项与建议；结论只进记录，不自动改配置。

控件作用说明
发起分析选命令 + 时间范围（或关键词），点「开始分析」采样命中日志送模型，长文本按规则裁剪
LLM 配置项目级模型与提供方（缺省用平台默认）密钥只回显掩码，修改才需重填

5.18 权限矩阵（所有登录用户可见）

区域内容怎么用

7.1 · 权限管理（角色即权限）

上表回答「每个角色能做什么」。权限完全由角色天然决定——没有「按人赋权」，也没有例外层：同一角色在任何项目里的默认权限一致，项目之间的差异只来自「你是否是该项目的成员、以及在那里是 PA 还是 M」。全局导航 /permissions 权限矩阵页（所有登录用户可见）把这套关系讲清楚：

  • 单一事实来源：后端权限点注册表 internal/auth/permissions.go 登记 18 个权限点（7 个平台级 + 11 个项目级），每个点标注「哪些角色默认拥有 + 它管什么 + 生效方式」；页面直接渲染这张注册表，代码即文档，与真实鉴权一致。
  • 左选角色 · 右看权限：左侧角色栏列出 4 个角色（平台管理员 A / 平台主管 S / 项目管理员 PA / 项目成员 M）与各角色当前人数；选中后右侧按「平台级 N 项 / 项目级 N 项」分组列出该角色拥有的全部权限点，每行给出权限名、作用说明与权限点标识（如 project.config.write）。
  • 进入即看自己：页面默认选中当前登录用户的角色，先回答「我有什么」。底部另有「我的角色」条，一眼确认自己的角色与权限计数。
  • 判定规则：平台级点由全局角色（A / S）决定；项目级点在「你是该项目成员」时按成员角色生效（PA 可写、M 只读），A / S 全局天然通过。唯一判定入口是 PermAllowed(user, projectID, key)，纯角色计算，不查任何覆盖表。
  • 真实生效点：platform.admin（平台设置全部路由）、project.view（项目可见）、project.admin（配置写 / 成员 / 客户端绑定 / LLM 配置总闸）为三个汇聚闸门；其余细粒度权限点先「登记可见」（标注「随汇总生效」），逐点独立判定在后续版本接入。
  • 不存在锁死风险：权限管理页不提供任何写操作——没有任何接口能单独改某个人的权限。角色只在「创建用户」与「添加项目成员」两处决定，因此不存在把自己或他人锁在外面的可能。
  • 审计：角色相关变更走既有动作留痕：user.create（建号时定全局角色）、member.add / member.remove（项目内角色）。

9 · 常见问题

搜索没有结果，怎么判断哪一步的问题？

先看 Agent 结果状态：no_files／no_source_matched 说明是日志源路径或模式问题（找 PA 改配置）；no_match 说明找到了文件但没命中关键词（换关键词或放宽时间）；source_missing 说明路径已不存在（回滚或改配置）。

结果条数和预期不符，是被吞了吗？

看是否出现 partial_success：Agent 侧有 10MB / 10 万行上限，触顶即截断。缩小时间范围或加过滤条件，而不是重复重跑。

Agent 显示离线，任务会怎样？

离线 Agent 不参与派发；重新上线后会上报 running_jobs，中心补发未过期租约、对已取消任务补发取消，Agent 按 job_id 去重，因此不会重复产出结果。

为什么改配置之后要“提交生效”，不能直接改？

配置是版本化对象：每次修改生成新版本，Agent 拿到的是某个具体版本，因此结果可复现、可回滚。直接改会让“上次搜索用的是哪版配置”无法回答。

对话里让 AI 改配置，它真的会改吗？

不会自动改。它会生成“建议动作卡”，你点「确认执行」后走的就是页面同一个写接口（同样过 RBAC 与审计）；确认回执（含任务号 / 批次号）留在对话流里，接着说「取消刚才那个任务」也能直接执行。平台级对话缺项目上下文时会降级为引导回答。

LLM 没配好，页面还能用吗？

能。自然语言搜索走本地规则解析、日志搜索与配置管理完全不依赖模型；只有语义搜索、日志分析、对话需要模型，页面会给出前往「平台设置 · 公共模型配置」的引导。

appid / secret 丢了怎么办？

secret 只显示一次，无法找回；在项目里重新生成后，更新 Agent 配置并重启即可。旧 secret 立即失效。

批量搜索会不会影响线上？

并发与每 Worker 请求数由你控制，执行的是读日志命令（禁 shell、只读），但会产生真实 CPU/IO 与网络流量——压测请在低峰期并从小并发开始。

10.7 导航分层规范（一级三分域）

决策来源：议题 A1「全局导航已 8 项，是否需要重新分层」（client/discovery/nav-restructure/，五步发现循环 + 专家团：3 同意 / 1 非阻塞保留）。

项规则
三分域工作区（对话 / 项目 / 场景 / 工作台）· 平台（权限矩阵 / 平台设置 / 审计日志）· 更多（客户端下载）。分组标题是纯文本 <p class="nav-group">，不可点击；禁分隔线 / 计数 / 折叠
顺序按真实使用频率：对话 → 项目 → 场景 → 工作台（工作台在「工作区」域内后置；其去留由议题 A2 裁决）
可见性仍由路由 meta.roles 单一事实源决定：权限矩阵对所有角色可见（成员必须能自查「我有什么」）· 平台设置仅 A · 审计日志仅 A / S
二级页签平台设置页签只读路由 meta.nav = { group, label, order } 的显式声明，不推断路由结构；新增 /platform/* 路由必须声明，否则不出现在页签里（守护：e2e/nav-ia.spec.ts）
文案守护导航项文案纳入 e2e 断言，禁止出现已下线的能力描述。历史缺陷：权限矩阵悬停文案曾残留「管理员按人赋权」，而该能力已在权限模型 v8（角色即权限）中删除

实现位置：web/src/components/Sidebar.vue（三分域 + 顺序）· web/src/router/index.ts（meta.nav 显式声明）· web/src/components/platform/PlatformTabs.vue（派生渲染）。

为什么没有把「权限矩阵 / 审计日志」并进平台设置页签（R3b 后置）

  • 量化证据：NN/g 对 179 名用户 × 6 个站点的测试——把入口藏进一层后，桌面端导航使用率从可见的 48–50% 降到 27%，且作者明确指出「隐藏主要伤害那些页内没有直达链接的内容」。权限矩阵正是这类页面（成员的自查入口）。
  • 更硬的原因：平台设置页签栏当前只对管理员渲染，对成员而言「并入」等于完全不可达，不是「多一层」。
  • 参照与差异：Grafana 把 Manage users / Roles and permissions / Organizations 平级收在 Administration 域内，GitLab 的 Administer 域整体按角色显隐——两者都是「整域同一可见性」；而我们权限页全员可读、其余项仅 A / A·S，属「半开半闭域」，没有现成先例可照抄，因此不上马。
